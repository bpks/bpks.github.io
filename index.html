Featured project

A health-research data platform, end to end

A small data platform I built end to end. Daily files go through a bronze, silver and gold pipeline with data quality and privacy controls, into a star schema in SQL with row-level security, deployed and run as code. All data is synthetic.

health-data-platform

Synthetic data PySpark · T-SQL · Terraform

Each layer does one job. Bad rows go to quarantine with the rules they broke, instead of being dropped. Direct identifiers stay in the restricted zone.

  1. LandingDaily CSV extracts, untouched
  2. BronzeRaw strings, append-only, restricted
  3. SilverTyped, validated, pseudonymised, upserted
  4. GoldStar schema and monthly mart
  5. Azure SQLRow-level security and masking

Rows failing an error-level rule go to a quarantine table beside silver, with the names of the rules they failed.

Incremental and idempotent

Watermarks per entity and upserts where the latest change wins. Re-running a batch, or receiving a stale record, cannot corrupt anything. Tests prove both.

Quality and privacy

Rules with severities, a quarantine zone, salted pseudonyms, birth year instead of date of birth. The docs also say plainly what each control does not do.

Warehouse and security

Kimball star schema with one definition per measure, columnstore facts, MERGE procedures, row-level security, dynamic data masking and DBA health scripts.

Platform as code and operations

Terraform for dev, test and prod, a deploy workflow that plans, waits for a reviewer, then applies the reviewed plan, plus KQL alerts and an incident and change runbook.

Honest status. The Python pipeline is run and tested end to end on Spark 3.5 and 4. The T-SQL, Terraform, GitHub Actions, Databricks and Fabric parts are written and statically checked, but have not been run against live services. The repository lists exactly what was and was not verified.
